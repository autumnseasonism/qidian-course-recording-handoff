# 状态、依赖和资源

归档按Part/模块/课节保留正式视频、原始资料、核验、逐字稿、页面版及索引。唯一JSON清单字段items数组，module/sequence为课节ID，type/title/status/directory/recording_file标素材事实；full_transcription_status/slide_export_status/cross_check_status取pending/running/completed/needs_review/failed并附证据。录制通过不代表新增阶段通过。

在长期持久REPL（多次调用保留变量的交互执行会话）中更新清单或交接时，先核修改前恢复保护，从磁盘读取最新版本并与当前待写对象完整比较，再依据已保存的实际阶段证据更新。写后完整读回相关文件，并在下一次独立调用中核实际外层绑定的版本和关键状态字段与磁盘一致；函数内部赋值、写入成功或同次调用读回不能代替此项检查。不复用捕获旧状态的闭包继续写入。发现内存与磁盘版本或阶段不一致时，停止相关状态写入，先记录差异，再按实际工具支持从磁盘重新绑定、修正及复核；保留样片等历史与正式活动状态的边界，不因文字错误中断正常采集。此规则针对实际工具的绑定边界，不假定所有REPL语义相同。

用 scripts/check_archive.py --archive-root <已授权根> 只读查ID、正式文件身份/正时长、文件存在/非空、路径越界、阶段状态。needs_review/completed阶段须有对应的*_evidence JSON与formal_sha256匹配、记录输入字节数，并提供非空 outputs 字典（路径相对证据文件父目录，值为小写SHA256）；completed另须quality_status为completed/accepted。旧证据缺输出绑定时报告待补，不补造哈希或改变原质量结论。--verify-hashes只在采集和重任务都空闲时重新核对绑定输入及列出的输出哈希。它不打开视频、不查实时进程、不验证内容，证据文件自称accepted不构成质量证明，主Agent须先实际复核。清单只由主Agent改，新成果不可变，各处理任务独立目录，记录输入SHA256、job ID、起止、错误与下一步。重跑先查真实进程及匹配输入结果，不因观察超时重复启动。

环境依赖以根目录 dependencies.json 为准：Python3.9+，已安装官方FFmpeg/FFprobe；本地识别实际使用 numpy、faster_whisper 和兼容的本地模型；页面使用 numpy、Pillow、ReportLab、pypdf、python-pptx，PDF实际预览可用Poppler，PPT实际渲染需要已安装LibreOffice。先检查当前解释器的模块，不以另一解释器可导入冒充本次可用。技能不捆绑软件、账号或模型；这些是明确运行依赖，不是其他项目/技能路径依赖。UI通过当前运行时允许的接口和实际工具文档，自带采集脚本不控制网页。软件不明来源或新增权限遵循实时确认政策。

录制时不转写/转码/批量提帧/回放，先一个重任务；实测资源余量、掉帧和同步之后才增加并发，不从低CPU使用率推断可并行。用户明确授权才委派，子Agent不控制同一浏览器/覆盖总清单，重任务取得资源许可后启动。

文件改动前遵循本地恢复规则，保存完整备份并读回校验，原件与备份映射明确。技能运行产物、测试、快照和包放技能树外；不初始化用户通用目录Git、不记凭据、不上传课程。交接记录目标、有效授权、真实节点、失败方法及证据入口，不写密码或日志全文。最终检查尚有可做工作则继续，不以保存交接结案。
